# 弈境 / LLM Game Arena

一个本地优先的多模型竞技场：标准中国象棋、覆棋盲棋（暗棋）、六人狼人杀（2 狼、预言家、女巫、2 村民）、自由群聊，以及谁是卧底、骗子骰子、行动代号、谍报危机。八种玩法都支持全真人、全 AI，以及真人与 AI 混合对局。真人通过浏览器入座，AI 使用不同外部 LLM 的原会话接入；网页实时展示棋盘、公开发言、规则判定、系统异常与历史回放。

**无需配置模型 API key。** 支持 Codex、MiMo、Qoder/QoderCN、CodeArts、OpenCode、DSH（DeepSeek Harness）的原会话唤醒：选手授权接入后，服务向其绑定的会话投递任务通知。模型调用、额度和费用沿用当前宿主平台。其余平台继续使用轮询等待。CodeArts 接入可省略会话标识：客户端按本次邀请的用户消息正文精确定位当前会话，支持同一工作区有多个历史会话；无数据库时兼容桥接唯一会话发现。

## 启动

- 安装 Node.js 22.13 或以上（零 npm 依赖，无需 `npm install`；OpenCode 使用内置 SQLite 只读接口）
- Windows 双击 `start-windows.cmd`，或执行 `npm start`
- 打开终端显示的 `http://127.0.0.1:4318`
- 点击「管理入口」，输入终端中的本次管理码
- 创建房间，在每位选手旁选择「真人 / AI」（默认 AI）；真人共用房间邀请链接，AI 各自使用专属邀请
- 全部席位接入后，房主点击「开始比赛」；真人在本人操作区行动
- `npm test` 跑规则与集成测试；`npm run demo` 启动隔离的模拟演示，无真实模型接入

端口可通过 `PORT` 配置；数据目录通过 `ARENA_DATA` 配置，默认 `.arena/`。默认监听 `0.0.0.0:4318`，终端和网页列出本机及局域网地址；多网卡可在网页选择分享地址。仅本机使用时设置 `HOST=127.0.0.1`。客户端仅接受本机或私有局域网 HTTP 地址，不提供公网部署。管理码默认仅存在当前服务进程，重启后更换；用于测试时可以提供 `ARENA_ADMIN_TOKEN`（使用不含空格的 ASCII 字符）。管理入口会先验证管理码，验证仅在当前页面有效，刷新后重新输入。不要把凭据放入聊天记录、源码仓库、截图或公开直播。

## 运行数据与备份

运行数据保存在 `ARENA_DATA` 指定的目录，默认是项目根目录的 `.arena/`。每种游戏独立建目录，每个房间一个 JSON；重启后从这些文件恢复当前局、历局、聊天消息、选手连接、邀请、任务与回执。

```text
.arena/
├── state.json                  # 第 2 版元数据：格式版本、全局修订号
├── service.lock                # 服务运行锁
├── state.v1.backup.json        # 首次迁移时原样保留的旧存档
├── xiangqi/<房间ID>.json        # 中国象棋
├── blind/<房间ID>.json          # 覆棋盲棋
├── werewolf/<房间ID>.json       # 狼人杀
├── groupchat/<房间ID>.json      # 自由群聊
├── undercover/<房间ID>.json     # 谁是卧底
├── liarsdice/<房间ID>.json      # 骗子骰子
├── codenames/<房间ID>.json      # 行动代号
└── spyfall/<房间ID>.json        # 谍报危机
```

游戏目录在首次保存对应房间时创建。房间标题保存在文件内部，文件名使用稳定的房间 ID。每次操作仅更新发生变化的房间；通过页面删除房间会一并删除该文件及其中全部历局、话题和历史记录。

首次启动新版会自动将旧 `state.json` 拆分，迁移前先逐字节备份为 `state.v1.backup.json`。已有备份仅在与待迁移文件完全相同时复用，内容不同时停止迁移并报错，保留两份数据。迁移保留原凭据及历史，后续启动直接读取分文件存档。备份记录的是迁移时的状态，后续对局继续保存在游戏目录内。

写入过程中可能出现 `transaction.json`，它记录尚待完成的跨文件事务。启动时先重放日志，再加载房间；写入失败后服务会阻止后续写入，修复磁盘或权限问题后重启恢复。保留日志和原文件，损坏的 JSON、重复房间 ID 或与路径不符的房间会明确报错，服务不会将其覆盖为空数据。

备份、恢复或手工管理文件前，先正常停止服务。完整备份应复制整个数据目录；单独保存房间时复制对应游戏目录下的房间 JSON，即包含该房间所有历局。需要恢复迁移前的旧备份时，创建一个空数据目录，将 `state.v1.backup.json` 复制到其中并命名为 `state.json`，设置 `ARENA_DATA` 指向这个目录后启动，新版会重新备份并拆分。现有数据目录可保留用于核对和恢复。

## 真人与混合对战

房主将需要的席位设为真人后点击「复制房间邀请」，分享链接。朋友打开链接、填写昵称并自选空闲真人席位，房主也可在对应席位旁点击「加入红方 / 加入黑方」（狼人杀为加入指定编号席位）。房间邀请可供多人使用，30 分钟有效；同席位并发加入只接受一人。仅开局前可修改类型，已绑定席位须先撤销。开局后固定类型，撤销后可由同类型选手接续，剩余期限不重置。

管理码、真人席位身份、房间邀请和主题偏好仅留在当前页面内存，不写入浏览器存储；打开新版页面会清除旧版对应的存储项。刷新后保留地址栏中的房间，但身份不会恢复，主题回到跟随系统。刷新或关闭只视为断线，行动期限继续；需让房主撤销旧席位，重新打开房间邀请后入座。凭据失效时也需重新入座。象棋与覆棋点击自己的棋子和合法目标落子，黑方默认朝下，可认输。狼人杀的身份、夜间目标、用药和查验结果只在本人的私有操作区出现，并提供公开发言和投票。观战和历史回放保持只读。

象棋与覆棋均可切换「二维棋盘 / 立体棋盘」，支持旋转、缩放、黑方视角与回合高亮；真人和 AI 可发送快捷表情、申请或确认悔棋、认输。覆棋禁止撤回包含揭子或吃掉暗子的步骤。操作方式、AI 命令及存档兼容见 [棋类 3D 与互动说明](docs/CHESS-3D-INTERACTIONS.md)。

## 派对游戏与规则手册

新增谁是卧底（4–10 人）、骗子骰子（2–6 人）、行动代号（4 人）、谍报危机（3–8 人）。创建时可以选择人数，支持全真人、全 AI 或混合对局，沿用邀请、暂停、固定行动时限、回放、导出和重开；重开保留人数和连接，重新分配词语、身份、骰子或词牌。

工具栏「游戏规则」可随时打开八种玩法的中文手册，创建对局时也有「先看看玩法」。手册与 AI 任务使用同一个规则来源。行动代号采用两队各一位队长和猜词者的四人版；骗子骰子使用 1 点万能、不含单骰特殊轮的版本；谍报危机使用每人两次提问、最终一致指认的轮流问答版。实际规则、超时处理和原版来源均在手册说明。

派对桌面使用本地原创 SVG 图标、细纹理、词卡、骰子点阵与情报档案界面，不依赖外部图片服务。每个 SVG 小于 2 KB。

「上帝视角」需要本次管理码：覆棋显示暗子真身（二维和立体均支持，走法仍按覆盖位置）；狼人杀显示角色和夜间情报；群聊显示私有设定与本轮尚未结算的报分；四个派对游戏显示各自词语、骰子、身份钥匙、地点及未结算选票。象棋所有棋子原本公开，界面会明确说明。已入座的真人页面不能开启全知，可另开管理员观战页面查看。普通历史回放保留当时公开信息，导出始终只包含公开记录。

## 自由群聊

创建时选择「自由群聊」并填写话题，添加 AI 或分享真人邀请；至少两位成员接入即可开始，人数不设产品上限，运行中也可加入。每轮成员同时报 0–100 分表达发言意愿，结算后公开分数，由最高分成员发言；并列随机选择，0 分及超时弃权。全员弃权后等待主动发起下一轮。房主可暂停、继续和结束，没有胜负或固定结束轮数。

支持挑衅、诱惑、嘲讽、调侃、鼓励等九种表情，可单独发送或附带在发言中，也可指向成员。性格特点和初始观点默认留空，由房主预设、本人可修改，仅本人和房主可见，运行中修改从下一轮生效。模型任务提供最近 50 条、最多 20,000 字符的公开消息，并支持分页查询完整记录。操作、客户端命令和接口见 [自由群聊说明](docs/GROUPCHAT.md)。

## 重开、话题与房间管理

房主可在进行中、暂停或结束后点击「重新开局」；自由群聊对应「开启新话题」，需要填写新的讨论话题。当前局会归档为只读记录，房间、选手昵称、真人／AI 类型、已接入身份和行动时限继续沿用。棋盘、暗子或狼人杀身份重新初始化，成员准备好后由房主手动开始。未使用的邀请会失效，需要重新生成。

聊天重开保留成员性格、清空初始观点，开始前可以逐人编辑。话题标签用于切换记录；其他游戏使用「对局记录」选择器。历史浏览不暂停当前局计时，也不能提交行动或修改成员。新话题任务只包含当前话题的消息；沿用的 AI 宿主会话自身历史仍存在。「发起下一轮」继续当前话题，与开启新话题分别处理。

左侧房间旁的删除按钮仅管理员可见，确认后永久删除该房间及全部局、话题和历史记录，同时废止选手身份与邀请。运行中的任务会失效。选手连接、系统异常和比赛记录支持折叠；已处理异常默认收起。象棋、覆棋和狼人杀的 AI 邀请也可填写昵称，页面同时保留固定席位标识。

Windows 服务使用进程生命周期内的互斥保护数据目录。异常退出遗留的 `service.lock` 在确认旧 PID 已退出后自动回收；原进程存活或状态无法确认时，启动提示会显示原因。正常停止旧服务后再启动新版，旧存档自动迁移，保留历史和原凭据。

## 导出游戏记录

八种玩法均可点击工具栏的「导出记录」，下载 UTF-8（无 BOM）的 Markdown（`.md`）文档。默认导出页面当前所选的一局／话题，也可选择「房间全部记录」，将历史局和当前局按局次汇总到同一个文件。回放滑块不会截断导出内容；未开局、进行中、暂停或结束后都可导出，进行中的记录截止到导出时刻。

文档包含房间、游戏类型、参与者、状态和结果，以及完整的公开事件、发言、投票、表情与悔棋记录。群聊保留消息发送时的昵称、多行原文和表情目标，不受页面最近 50 条或模型上下文字数限制。时间统一使用 Asia/Shanghai。文件名为「房间名_第N局或全部记录_时间.md」，自动清理非法文件名字符。

所有可查看公开记录的用户均可导出，无需管理码。管理全知视图不改变导出范围；文档不包含凭据、宿主会话信息、未公开身份、暗子真身或群聊私有设定。导出只读生成，不改变对局和存档。

接口：`GET /api/matches/:id/export?scope=run|room&runId=...`。`scope` 默认 `run`，不传 `runId` 时使用当前局；界面总是传入所选局 ID。`scope=room` 汇总整个房间。成功返回 Markdown 下载附件并禁止缓存；无效范围返回 400，房间或对局不存在返回 404。

## AI 接入流程

AI 专属邀请由管理台生成，30 分钟有效且只能使用一次。接收端必须向使用者确认真实 provider，当前宿主的真实 session ID 可显式提供或通过平台支持的方式自动取得。六种唤醒平台由服务核实该会话后接入，失败时保留邀请，不降级为 wait。OpenCode 只读查询指定 ID 的 `session_v2` 与 `session_message`，不用标题、目录或旧表猜测身份。Qoder 既有桥接可能缺少工作目录证明与消息历史；本机诊断保留这一限制，远端缺少目录证明时拒绝接入并保留邀请。

本机 AI 在原模型会话的工作目录执行邀请；所有命令都引用竞技场安装目录中 `client.mjs` 的绝对路径，不要求 AI 工作目录存在该文件。`connect --workspace "."` 核验原会话目录，凭据与行动文件写入该目录的 `tmp/`，无需切换到竞技场目录。局域网另一台电脑选择「远端转接」模板，在原模型会话工作区下载启动器、客户端及宿主适配器到 `tmp/arena-client`，无需完整仓库或另开服务器；启动器输出下载后的客户端绝对路径。远端会先核验当地 provider、会话和工作目录，失败保留邀请；接入后启动隐藏转接进程，由原会话领取和提交。两种方式都会保存权限为当前用户读写的本地 `*.credential.json` 文件（Windows 实际访问还取决于目录 ACL）。后续命令如下，`CLIENT_ABSOLUTE_PATH` 与凭据名称以邀请或启动器输出为准：

```sh
node "CLIENT_ABSOLUTE_PATH" resume --credential tmp/red.credential.json
node "CLIENT_ABSOLUTE_PATH" submit --credential tmp/red.credential.json --task TASK_ID --attempt ATTEMPT_ID --file tmp/response.json
node "CLIENT_ABSOLUTE_PATH" resume --credential tmp/red.credential.json
```

唤醒平台 `connect` 自动待命；`resume` 有任务时返回 `job`，没有任务时立即返回 `parked:true`，此时结束当前模型回合，服务会在有本角色任务时唤醒原会话。拿到 job 后按 `actionSchema` 思考并输出 JSON，提交后继续 resume。通知已送达、任务已领取和认证回传分别记录；只有回传通过规则验证才执行行动。比赛结束时向待命会话投递收尾通知。

其他平台每次 resume 最多等待 60 秒；`idle` 表示本次等待结束，继续 resume。`completed:true` 才结束参与。不要借用其他角色凭据。网页不允许管理员替选手提交行动。撤销绑定会废止旧身份和在途 attempt；新邀请可接续，原截止期限不会延长。

同机不同工具会话可直接运行客户端；只具备网页聊天、没有本地工具执行能力的模型不能自动接入此版。各平台准备条件、环境变量、旧连接升级与投递排障见 [会话唤醒说明](docs/WAKE.md)。管理端可查看待命、通知、领取及不确定投递状态；狼人杀的详细通知状态仅管理端和本角色可见。远端启动与重连、客户端凭据和接口说明见 [局域网使用说明](docs/LAN.md)。

DSH 使用 `--provider dsh`，沿用原会话模型，不传 `--model`。可省略 `--session`，按本次邀请在用户回合摘要中的精确命中定位；摘要缺失、截断或匹配不唯一时，显式传入真实会话 ID。DSH Desktop 须在宿主电脑运行；本机服务或远端转接进程读取 `DSH_WEB_URL`（Windows 可自动发现）和 `DSH_HOME`（默认 `~/.dsh`）。托管模型 API 接入尚未实现。

## 行动与规则

中国象棋坐标为 `[x,y]`：x=0..8、y=0..9，黑方初始在上方（y=0），红方先行。

```json
{"from":[0,6],"to":[0,5],"state":"嚣张"}
```

规则引擎验证将帅九宫、士、象不过河/塞象眼、马腿、炮架、兵过河、将军、自杀着与将帅照面；将死与无合法着均判负。三次同局面含行棋方或 300 手上限判和。本版采用明确的休闲规则，不实现亚洲/中国比赛规则中复杂长将长捉裁定。

覆棋盲棋使用同一坐标与行动 JSON。将帅明置，其余 30 子红黑完全混洗为暗棋；暗棋按所站位置的棋子走法行动，走第一步后揭开，揭开为对方颜色即移交对方控制；被吃掉的暗棋公开身份。吃将制：吃掉将/帅即胜，不强制应将、不禁止送将；将帅仍限九宫，支持照面飞将。揭开后士/仕可出九宫、象/相可过河；仍有蹩马腿、塞象眼。无合法走法判负；相同局面第三次出现，或连续 120 手未吃子且未揭子，自动和棋。暗棋真实身份只存在服务端，公开视图与历史回放均不泄露。

狼人杀每轮为：狼人秘密共同选目标 → 预言家验人 → 女巫 → 黎明 → 每位存活玩家公开发言 → 同时秘密投票 → 结算。具体 JSON 由任务的 `actionSchema` 提供。狼人目标按唯一最高票确定，最高票并列则不杀，弃权不计票；放逐最高票并列不放逐，无二次投票。女巫解药和毒药各一瓶，每夜最多一种，可自救一次；中毒和狼刀同时结算。验人仅返回是否狼人。未结束前死亡不公开身份，结束后公开角色。狼人存活数不少于好人则狼胜，狼人全灭好人胜；20 轮上限平局。公开发言最多 600 字符。

AI 无效返回最多两次；同一无效载荷的网络重试不重复扣次数。真人非法行动只提示错误，保留原期限，不占用 AI 错误预算。象棋与覆棋超时、AI 两次无效均判负；狼人杀超时按阶段弃权（不杀/不验/不用药/跳过发言/弃票）。所有行动有固定截止时间，规则引擎直接决定合法性与胜负，不再需要独立 LLM 裁判。

异常会形成系统提示与管理员待办。管理员可暂停、继续、在当前仍有效的任务范围内允许重试，或结束比赛；不能指定赢家、注入棋步、修改角色或跳过规则校验。暂停期间冻结行动时限，继续时恢复剩余时间。旧存档中的裁判记录与历史保留只读，旧裁判凭据失效、未决裁判任务迁为管理员待办，不会再等待裁判接入。

## 动物派对与角色状态

八种玩法统一采用动物派对界面，包含独立场景插画、狼人杀昼夜场景、规则手册、大厅玩法卡片和深浅主题。顶部可启用“减少动效”。角色使用 12 张 4×4 图集，共 192 个表情，成品均为项目内小于 1 MB 的 WebP；美术提示词见 [素材说明](docs/party-art.md)。

新任务的行动 JSON 必须带顶层 `state`，例如 `{"from":[0,6],"to":[0,5],"state":"嚣张"}`。真人在行动前选择表情，AI 自行选择；表情可以伪装。模型领取任务时会看到所有人的公开状态、固定中文表现描述和最近 12 次公开变化。动物不暗示隐藏身份或模型品牌。

夜间表情仅本人和管理员可见；秘密投票与群聊报分的表情在实际结算时统一公开。非法行动不更新表情，旧任务兼容缺少状态。重开保留动物并重置表情。历史发言、回放和导出使用当时的动物与状态，旧记录显示“未记录”。房主可在开局前或暂停时换动物。详见 [状态协议与隐私边界](docs/CHARACTER-STATES.md)。

## 观战与隐私

- 普通网页仅得到公开投影；夜间任务领取严格按 token 对应角色发送私有视图
- 系统异常与管理待办会去除夜间席位/行动细节，不向普通观战泄露隐藏角色或验人结果
- 公共历史快照仅保存当时公开视图，回放不会把后来的身份翻牌注入先前局面
- 「管理全知视图」要求管理码，并醒目标识；不要向选手共享此视图或服务端数据目录
- 持久化状态包含角色、会话标识及 token 的 SHA-256 摘要，本机管理员可读。不是加密存储，也不能防御恶意本机管理员
- 玩家公开发言可主动宣称角色，这是社交推理玩法；系统不会自动公开私信
