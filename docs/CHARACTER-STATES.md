# 角色状态协议

所有八种玩法共用 `lib/presentation.mjs` 的 12 种动物和 16 种固定中文状态。动物优先不重复，超过 12 位时选择使用次数最少的动物；与身份、阵营、模型品牌无关。真人和 AI 使用相同头像与状态。

## 行动格式

新建任务的 `stateProtocol` 为 `1`，每次提交都必须在行动 JSON 顶层给出合法 `state`：

```json
{"from":[0,6],"to":[0,5],"state":"嚣张"}
```

服务端先校验并取出状态，原行动继续交给相应规则引擎。非法行动不更新状态；额外的自定义状态描述不被接收。同一回执的摘要包含整个行动及状态，完全重复的网络提交不重复广播，修改状态后重提同一回执会冲突。

升级前已经发出的旧任务不补写协议标记，可以省略 `state`，沿用原公开状态。升级不撤销旧连接、行动期限、回执或进行中的任务。

固定状态依次为：平静、老实、真诚、无辜、嚣张、得意、狡黠、挑衅、思考、疑惑、紧张、惊讶、委屈、沮丧、愤怒、开心。

## 可见性

- 普通公开行动成功后，状态与行动一起公开，持续到下一次公开行动。快捷表情仍作为短时互动使用。
- 狼人杀夜间表情只出现在本人 `ownPresentation.privateState` 和管理员全知视图中，公共头像继续使用原状态；黎明不会自动公布这些表情。真人白天的状态选择默认回到原公开状态，避免无意带出夜间表情。
- 狼人杀、谁是卧底、谍报危机的秘密投票，以及群聊报分，将状态封存到实际公开结算，再一次性发布。普通接口不提供未提交者名单，封存期间不产生公开状态事件或行动者时间戳。
- 超时促成公开结算时，可以发布先前已经封存的状态。房主直接结束或重开，不会把未结算的状态当作公开行动发布。

管理员通过已鉴权的 `POST /api/participant-appearance` 调整头像，正文包含 `match`、`seat`、`animalId`、`expectedRunId`。只允许开局前或暂停时调整。群聊运行中加入的成员自动分配动物。重开保留动物，状态重置为“平静”。

## 模型输入与历史

每次领取任务的 `job.view` 包含：

- `participants`：所有参与者当时的公开 `animalId` 和 `state`。
- `stateCatalog`：固定中文状态、格子坐标与统一的中文外在表现描述。
- `recentStateChanges`：最近 12 次公开状态变化及当时的动物、昵称、时间。
- `stateGuidance`：明确说明状态是主动选择的表演、可以伪装，不是系统认证的真实性或可信度。

历史快照、公开事件的 `eventPeople`、聊天消息的 `sender` 与派对发言的 `author` 保存当时的形象。回放和导出不借用当前头像或当前状态。旧记录缺失形象字段时显示“未记录”。固定状态目录不重复存入每条历史快照，以控制存档大小。

模拟模型测试验证这些字段和中文表现描述确实进入领取任务的输入，并检查模拟决策可以读取它们。这不表示真实模型必然改变判断；真实行为效果仍取决于模型及对局。
